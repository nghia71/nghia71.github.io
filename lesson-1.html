What Lesson 1 is for

Every problem below is solved with real math first — a factorization, a recurrence, a divisibility argument, a search whose completeness is proved — and a short Python program second, so the code expresses that math directly instead of guessing numbers until one works. This is exactly the standard your own contest submissions are held to: read the scoring rules below, then study how each example meets them.

Problems marked “Pi Journal” come from the Math Challenge section of Pi Journal and are used with the journal’s permission; where Pi asks to “find all” or “prove”, the problem has been given a single numerical answer so it can be checked by a program.

What’s required and acceptable for a contest submission

Read this before you write your first line of contest code. Every worked example below is itself a submission that would pass all of these rules — that’s the point of reading them closely, not just the answer.

File format

  • One .py text file per problem you attempt. Plain Python source, nothing else. On contest day you submit it by pasting the whole file into the submission form (select all, copy, paste): indentation is kept exactly, and the form saves it as a .py file for grading.
  • You may submit the same problem again; the last submission before the 8:45 close is the one graded.
  • Not accepted: a PDF, a Google Doc, a Jupyter notebook (.ipynb), a screenshot of code, a file renamed to end in .py that isn’t actually Python.

Middle School

MS · Problem 1 · Easy Algebra

A shop sells two kinds of rice, type A and type B. Every bag of type A weighs \(25\) kg and every bag of type B weighs \(40\) kg. The shop has signed a contract to deliver \(1\) tonne of rice, using both kinds. What are the largest and the smallest possible total numbers of bags the shop can deliver?

Source: Pi Journal (pi.edu.vn), Problem P941. Used with permission.

Let \(m\) and \(n\) be the numbers of bags of type A and type B, with \(m, n \ge 1\). Then \(25m + 40n = 1000\), i.e. \(5m + 8n = 200\). Since \(8n\) and \(200\) are both multiples of \(8\), so is \(5m\); as \(\gcd(5,8)=1\), \(8 \mid m\). In the same way \(5 \mid n\). Write \(m = 8a\), \(n = 5b\): the equation becomes \(40a + 40b = 200\), so \(a + b = 5\) with \(a, b \ge 1\). The total is \(m + n = 8a + 5b = 3a + 25\), which grows with \(a\). So there are exactly four deliveries (\(a = 1, 2, 3, 4\)); the smallest total is \(28\) bags and the largest is \(37\). The code lists exactly those four cases — no guessing.
# MATH: 25m + 40n = 1000  <=>  5m + 8n = 200.
# 8 | 5m and gcd(5,8)=1 force 8 | m; likewise 5 | n.
# With m = 8a, n = 5b the equation is a + b = 5 (a, b >= 1),
# so the ONLY possible deliveries are a = 1, 2, 3, 4.
totals = []
for a in range(1, 5):          # a + b = 5, both at least 1
    b = 5 - a
    m, n = 8 * a, 5 * b        # bags of type A and type B
    assert 25 * m + 40 * n == 1000
    totals.append(m + n)       # = 3a + 25
    print(f"A bags = {m:2d}, B bags = {n:2d}, total = {m + n}")

print("smallest:", min(totals))   # 28
print("largest: ", max(totals))   # 37

MS · Problem 2 · Easy Geometry

How many non-congruent triangles have integer side lengths and perimeter \(40\)?

List each triangle once by sorting its sides: \(a \le b \le c\) with \(a + b + c = 40\). Two triangles with the same three side lengths are congruent (SSS), so each sorted triple is one triangle. The only other condition is the triangle inequality, and with \(c\) the longest side it reduces to \(a + b > c\), i.e. \(40 - c > c\), so \(c \le 19\). Because \(c\) is the largest of three numbers adding to \(40\), \(3c \ge 40\), so \(c \ge 14\). For each \(c\) from \(14\) to \(19\), the pair \((a, b)\) must satisfy \(a + b = 40 - c\) and \(a \le b \le c\). That is a small, provably complete list — the code counts it.
# MATH: sort the sides a <= b <= c, a + b + c = 40.
# Triangle inequality with c longest: a + b > c  <=>  c < 20.
# c is the largest of three numbers summing to 40, so 3c >= 40, c >= 14.
P = 40
count = 0
for c in range(14, 20):            # 14 <= c <= 19
    s = P - c                      # a + b = s
    for b in range(1, c + 1):      # b <= c
        a = s - b
        if 1 <= a <= b:            # a <= b keeps each triangle once
            count += 1
print(count)                       # 33

MS · Problem 3 · Medium Combinatorics

Minh climbs a staircase of \(12\) steps. With each stride he goes up either \(1\), \(2\) or \(4\) steps. In how many different ways can he reach the top? (For example, \(4, 4, 2, 1, 1\) and \(1, 1, 2, 4, 4\) are different ways.)

Let \(w(n)\) be the number of ways to climb \(n\) steps. Look at the last stride: it is \(1\), \(2\) or \(4\) steps, and before it Minh had climbed \(n-1\), \(n-2\) or \(n-4\) steps in any valid way. These cases don’t overlap and cover everything, so \[ w(n) = w(n-1) + w(n-2) + w(n-4), \qquad w(0) = 1, \] with \(w\) of a negative number equal to \(0\). Building the table from \(w(0)\) up to \(w(12)\) takes twelve additions — far better than listing the hundreds of ways one by one.
# MATH: split by the LAST stride (1, 2 or 4 steps):
#   w(n) = w(n-1) + w(n-2) + w(n-4),  w(0) = 1 (the empty climb).
N = 12
STRIDES = (1, 2, 4)
w = [0] * (N + 1)
w[0] = 1
for n in range(1, N + 1):
    w[n] = sum(w[n - s] for s in STRIDES if s <= n)
print(w)        # the whole table, so you can check small cases by hand
print(w[N])     # 520

MS · Problem 4 · Medium Number Theory

In the division below, different letters stand for different digits, and no number begins with the digit \(0\): \[ \overline{AHHAAH} \div \overline{JOKE} = \overline{HA}. \] Find \(\overline{JOKE}\).

Source: Pi Journal (pi.edu.vn), Problem P912. Used with permission.

The division says \(\overline{AHHAAH} = \overline{HA} \cdot \overline{JOKE}\). The key observation is that everything is decided by the two digits \(A\) and \(H\): once they are chosen, the six-digit number \(\overline{AHHAAH}\) and the divisor \(\overline{HA}\) are fixed, and \(\overline{JOKE}\) can only be their quotient. So the search is over at most \(9 \times 8 = 72\) pairs (\(A, H\) nonzero because they start numbers, and different). For each pair we check three things: the division is exact, the quotient has four digits, and the six letters \(A, H, J, O, K, E\) are six different digits. The search is complete by construction, and exactly one pair survives: \(H = 7\), \(A = 3\), giving \(377337 = 73 \times 5169\).
# MATH: AHHAAH = HA * JOKE, and A, H alone determine AHHAAH and HA,
# so JOKE = AHHAAH / HA. Only 9 * 8 = 72 pairs (A, H) exist
# (both nonzero, since each starts a number; different letters).
answers = []
for A in range(1, 10):
    for H in range(1, 10):
        if A == H:
            continue
        big = int(f"{A}{H}{H}{A}{A}{H}")    # AHHAAH
        HA = 10 * H + A
        if big % HA:
            continue                       # division must be exact
        JOKE = big // HA
        if not 1000 <= JOKE <= 9999:
            continue                       # JOKE has 4 digits, J != 0
        letters = [A, H] + [int(d) for d in str(JOKE)]
        if len(set(letters)) == 6:          # six letters, six digits
            answers.append((big, HA, JOKE))
print(answers)          # [(377337, 73, 5169)]

MS · Problem 5 · Hard Number Theory

A positive integer \(n\) is called self-dividing if its digits are pairwise different and each of its digits divides \(n\). Find the largest self-dividing number.

Source: Pi Journal (pi.edu.vn), Problem P951. Used with permission.

A self-dividing number has no digit \(0\) (nothing is divisible by \(0\)). No 5 in a big one: if \(5\) is a digit, \(n\) is a multiple of \(5\), so it ends in \(5\) and is odd — then \(2, 4, 6, 8\) can’t be digits, leaving at most the five digits \(1, 3, 5, 7, 9\). Without 5, the digits come from \(\{1,2,3,4,6,7,8,9\}\), whose sum is \(40\). All eight can’t be used: then \(9 \mid n\), but the digit sum \(40\) is not a multiple of \(9\). So the best we can hope for is seven digits. If \(9\) is among them, the digit sum must be a multiple of \(9\): \(40 - x \equiv 0 \pmod 9\) forces the missing digit to be \(x = 4\). So a seven-digit self-dividing number that starts with \(9\) must use exactly the digits \(\{1,2,3,6,7,8,9\}\) and be divisible by \(\operatorname{lcm}(1,2,3,6,7,8,9) = 504\). Any seven-digit candidate without a \(9\) starts with at most \(8\), and anything shorter is smaller still. So: check the \(7! = 5040\) arrangements of those seven digits for divisibility by \(504\) and take the largest. (If none existed we would have to widen the search — the code checks that one does.)
# MATH (see the note):
#  * no digit 0; a digit 5 forces an odd number ending in 5 -> at most 5 digits
#  * digits from {1,2,3,4,6,7,8,9} (sum 40): all 8 impossible, since 9 | n
#    but 9 does not divide 40 -> at most 7 digits
#  * 7 digits including 9: digit sum must be a multiple of 9 -> drop the 4.
# So the best candidates use exactly {1,2,3,6,7,8,9} and are multiples
# of lcm(1,2,3,6,7,8,9) = 504. Anything else is smaller.
from itertools import permutations
from math import lcm

digits = [1, 2, 3, 6, 7, 8, 9]
L = lcm(*digits)
print("lcm =", L)                                   # 504

best = 0
for p in permutations(digits):                      # 7! = 5040 numbers
    n = int("".join(map(str, p)))
    if n % L == 0:                                  # every digit divides n
        best = max(best, n)
print(best)                                         # 9867312
assert best > 0 and str(best)[0] == "9"  # beats every candidate without a 9

High School

HS · Problem 1 · Easy Number Theory

In how many ways can \(3150\) be written as the sum of two or more consecutive positive integers? (For example, \(9 = 4 + 5 = 2 + 3 + 4\) can be written in \(2\) ways.)

A run of \(k \ge 2\) consecutive integers starting at \(a \ge 1\) has sum \(\dfrac{k(2a + k - 1)}{2}\). Setting this equal to \(3150\) gives \[ k \cdot (2a + k - 1) = 6300. \] The two factors \(k\) and \(m = 2a + k - 1\) have opposite parity (their difference \(2a - 1\) is odd), and \(m > k\) because \(a \ge 1\). Conversely, any factorization \(6300 = k \cdot m\) with \(2 \le k < m\) and \(k, m\) of opposite parity gives back a valid \(a = (m - k + 1)/2 \ge 1\). So we only need to walk through the divisors of \(6300\). (Counting them by hand gives a neat formula: the answer is the number of odd divisors of \(3150\), minus \(1\) for the one-term “sum” \(3150\) itself.)
# MATH: k consecutive integers from a sum to k(2a + k - 1)/2, so
#   k * m = 6300,  with m = 2a + k - 1.
# m - k = 2a - 1 is odd  -> k, m have opposite parity;  a >= 1 -> m > k.
# Every such factor pair (k >= 2) gives exactly one valid run.
N = 3150
count = 0
for k in range(2, 2 * N + 1):
    if k * k >= 2 * N:            # need k < m = 2N/k
        break
    if (2 * N) % k:
        continue
    m = 2 * N // k
    if (m - k) % 2 == 1:           # opposite parity
        a = (m - k + 1) // 2
        assert sum(range(a, a + k)) == N
        count += 1
print(count)                       # 17

# cross-check with the odd-divisor formula
odd_divs = sum(1 for d in range(1, N + 1, 2) if N % d == 0)
print(odd_divs - 1)                # 17

HS · Problem 2 · Easy Geometry

On a sheet of graph paper, a straight segment is drawn from the lattice point \((1200, 700)\) to the lattice point \((4800, 3100)\). How many unit squares of the grid have interiors that the segment passes through?

Translate so the segment runs from \((0,0)\) to \((3600, 2400)\). Let \(g = \gcd(3600, 2400) = 1200\). The lattice points on the segment are exactly \((3t, 2t)\) for \(t = 0, 1, \dots, 1200\), so they cut it into \(1200\) identical pieces, each going from one lattice point to the next by \((3, 2)\). One piece, from \((0,0)\) to \((3,2)\), meets no lattice point in between, so every time it crosses a grid line it enters a new square: it crosses \(3 - 1 = 2\) interior vertical lines and \(2 - 1 = 1\) interior horizontal line, entering \(1 + 2 + 1 = 4\) squares. The pieces don’t share any squares (each piece stays in its own \(3 \times 2\) box), so the total is \(4 \cdot 1200 = 4800\). In general: \(\Delta x + \Delta y - \gcd(\Delta x, \Delta y)\). The code uses the formula and also checks it exactly, with fractions, against a direct square-by-square test on small cases.
# MATH: lattice points on the segment split it into g = gcd(dx, dy) equal
# pieces; each piece (dx/g, dy/g) touches no lattice point inside, so it
# enters 1 + (dx/g - 1) + (dy/g - 1) squares. Total: dx + dy - g.
from math import gcd
from fractions import Fraction as F

def squares_formula(dx, dy):
    return dx + dy - gcd(dx, dy)

def squares_direct(dx, dy):
    # the segment is t*(dx, dy), 0 <= t <= 1; it crosses the INTERIOR of the
    # square [i, i+1] x [j, j+1] iff the open t-intervals for x and y overlap
    count = 0
    for i in range(dx):
        for j in range(dy):
            lo = max(F(i, dx), F(j, dy))
            hi = min(F(i + 1, dx), F(j + 1, dy))
            if lo < hi:
                count += 1
    return count

# the formula agrees with the direct test on every small case
assert all(squares_formula(a, b) == squares_direct(a, b)
           for a in range(1, 13) for b in range(1, 13))

dx, dy = 4800 - 1200, 3100 - 700
print(dx, dy, gcd(dx, dy))        # 3600 2400 1200
print(squares_formula(dx, dy))    # 4800

HS · Problem 3 · Medium Algebra

A sequence is defined by \(a_1 = 2\), \(a_2 = \dfrac{5}{9}\), and \[ a_n = \frac{a_{n-2}\, a_{n-1}}{2a_{n-2} - a_{n-1}} \quad \text{for } n \ge 3. \] Then \(a_{2026} = \dfrac{p}{q}\) for relatively prime positive integers \(p\) and \(q\). Find \(p + q\).

Take reciprocals. With \(b_n = 1/a_n\), \[ b_n = \frac{2a_{n-2} - a_{n-1}}{a_{n-2}\,a_{n-1}} = \frac{2}{a_{n-1}} - \frac{1}{a_{n-2}} = 2b_{n-1} - b_{n-2}, \] i.e. \(b_n - b_{n-1} = b_{n-1} - b_{n-2}\): the reciprocals form an arithmetic sequence. Here \(b_1 = \tfrac12\), \(b_2 = \tfrac95\), so the common difference is \(\tfrac95 - \tfrac12 = \tfrac{13}{10}\) and \[ b_{2026} = \tfrac12 + 2025 \cdot \tfrac{13}{10} = 2633, \qquad a_{2026} = \tfrac{1}{2633}. \] So \(p + q = 2634\). The code does it both ways: the closed form, and the recursion itself run with exact fractions (no floating-point error).
# MATH: b_n = 1/a_n satisfies b_n = 2 b_{n-1} - b_{n-2}, so the
# reciprocals are ARITHMETIC: b_n = b_1 + (n - 1) d, d = b_2 - b_1.
from fractions import Fraction as F

a1, a2 = F(2), F(5, 9)
N = 2026

# 1) closed form from the math
b1, b2 = 1 / a1, 1 / a2
d = b2 - b1                        # 13/10
aN = 1 / (b1 + (N - 1) * d)
print(aN)                          # 1/2633

# 2) the recursion itself, exactly, as a check
x, y = a1, a2
for n in range(3, N + 1):
    x, y = y, x * y / (2 * x - y)
assert y == aN

print(aN.numerator + aN.denominator)    # 2634

HS · Problem 4 · Medium Combinatorics

The first \(16\) positive integers are written on \(16\) cards, one number per card. Let \(s\) be the number of different ways to put all \(16\) cards into two boxes, \(A\) and \(B\), so that the sum of the numbers in box \(A\) equals the sum of the numbers in box \(B\). (Two ways are different if some card is in a different box. Pi’s original problem asks to prove that \(s \ge 35\).) Find \(s\).

Source: Pi Journal (pi.edu.vn), Problem P871. Used with permission.

The numbers add up to \(1 + 2 + \dots + 16 = 136\), so each box must hold exactly \(68\). A placement is decided entirely by which cards go into box \(A\), so \(s\) is the number of subsets of \(\{1, \dots, 16\}\) with sum \(68\). Instead of checking all \(2^{16}\) subsets, count them with a subset-sum table: process the cards one at a time and keep, for every total \(t\), the number of ways to reach \(t\) using the cards so far. Adding card \(c\) means: every old way to reach \(t\) either skips \(c\) (still reaches \(t\)) or takes it (now reaches \(t + c\)). After all \(16\) cards, the entry for \(68\) is \(s\). The code also checks the answer by brute force over all \(2^{16} = 65\,536\) subsets.
# MATH: total = 136, so box A must hold exactly 68; a placement = the set
# of cards in box A. Count subsets with sum 68 by dynamic programming:
# ways[t] = number of ways to reach total t with the cards seen so far.
from itertools import combinations

cards = range(1, 17)
target = sum(cards) // 2            # 68
ways = [0] * (target + 1)
ways[0] = 1                         # the empty set
for c in cards:
    for t in range(target, c - 1, -1):   # go downward: each card used once
        ways[t] += ways[t - c]
s = ways[target]
print(s)                            # 1314

# brute-force check over all 2^16 subsets
check = sum(1 for r in range(17) for S in combinations(cards, r)
            if sum(S) == target)
assert check == s
print("s >= 35:", s >= 35)          # what Pi asked us to prove

HS · Problem 5 · Hard Number Theory

Let \(n\) be a positive integer with at least three positive divisors, and let \(1 = d_1 < d_2 < \dots < d_k = n\) be all of its positive divisors. Call \(n\) good if \(d_i\) divides \(d_{i+2}\) for every \(i = 1, 2, \dots, k-2\). How many good numbers \(n \le 2026\) are there? (Pi’s original problem asks for all good numbers.)

Source: Pi Journal (pi.edu.vn), Problem P877. Used with permission.

This is Pi’s classification, proved in its published solution. At most two primes: if \(p < q < r\) all divide \(n\), then \(r\) sits at some position \(d_i\) with \(i \ge 4\), and \(d_{i-2}\) is a divisor greater than \(1\) that must divide the prime \(r\) — impossible. So \(n = p^\alpha\) or \(n = p^\alpha q^\beta\) (\(p < q\)). One prime: the divisors are \(1, p, p^2, \dots\) and every \(n = p^\alpha\) with \(\alpha \ge 2\) is good. Two primes: the exponents can’t both be \(\ge 2\) (checking the first few divisors gives a contradiction either way), and the careful case check leaves exactly \[ n = p\,q^\beta \ (p < q,\ \beta \ge 1) \qquad\text{or}\qquad n = p^\alpha q \ (\alpha \ge 2,\ p < q < p^2). \] Once the characterization is known, counting \(n \le 2026\) is a job for code. We count with the classification and, independently, test the definition directly on every \(n \le 2026\) — the two counts must agree.
# MATH (Pi's classification): n is good exactly when
#   n = p^a        (a >= 2), or
#   n = p * q^b    (p < q primes, b >= 1), or
#   n = p^a * q    (a >= 2, p < q < p^2).
LIMIT = 2026

def factor(n):
    f, p = {}, 2
    while p * p <= n:
        while n % p == 0:
            f[p] = f.get(p, 0) + 1
            n //= p
        p += 1
    if n > 1:
        f[n] = f.get(n, 0) + 1
    return f

def good_by_classification(n):
    f = factor(n)
    ps = sorted(f)
    if len(ps) == 1:
        return f[ps[0]] >= 2
    if len(ps) == 2:
        p, q = ps
        return f[p] == 1 or (f[q] == 1 and q < p * p)
    return False

def good_by_definition(n):
    d = [k for k in range(1, n + 1) if n % k == 0]
    return len(d) >= 3 and all(d[i + 2] % d[i] == 0 for i in range(len(d) - 2))

c1 = sum(good_by_classification(n) for n in range(2, LIMIT + 1))
c2 = sum(good_by_definition(n) for n in range(1, LIMIT + 1))
print(c1, c2)       # 670 670
